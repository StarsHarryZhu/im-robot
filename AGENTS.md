# AGENTS.md

## 1. Role

im-robot is a host-only DeepSeek Harness plugin that connects a chat account to a session the caller chooses. It provides the `imRobot` service: `login` a WeChat account by QR code (Tencent iLink), `bind` it to a session, and from then on the messages of the person who scanned are prompted into that session (queued, or steering a running turn if the binding asks for it; a `/` line runs as a session command instead), with their images, files, voice, and video saved in the binding's media folder and named in the text, and the final assistant text of each turn they started goes back as plain text, split into short messages of `replyMaxChars` characters (default 100) at sentence ends, then commas, of many scripts, with any block the model wrapped in `<keep>…</keep>` delivered whole, through an outbox on disk that survives restarts and reconnects. The receive loop reconnects on its own with exponential backoff, and `status` says whether a binding is connected and, in plain Chinese, what last went wrong; `reconnect` restarts a connection now and `diagnose` checks a binding step by step, for the parent's WeChat settings panel. With `autoPush` on (the default), while the latest human input came from the chat, turns that no chat message started are answered on the chat too: a background worker's report (`subagent-settled`), an agent or team message, or a note a host plugin sends itself (`host-note`) goes through the outbox like a reply, and a reminder is pushed once; a turn with no text sends nothing, and neither does a turn whose whole reply is the configured `silentReply`. `send` reaches the account at any time. It is a sub-plugin of `dsh-assisstant`, which mounts it with `presets: [dsh-assisstant]` and `autoPush: false`, drives the "bind WeChat" flow through the service, and decides itself what goes out through `send`; it can also be installed on its own as one top-level row.

## 2. Constraints

- The `imRobot` interface is a contract with the parent package and must stay exactly: `login(bindingId, 'wechat', signal?)` yielding `qr` / `scanned` / `bound` or `expired` / `failed` (with a plain-Chinese `reason`), `bind(bindingId, { sessionId })`, `unbind(bindingId)`, `status(bindingId)` returning `{ bound, user?, sessionId?, connected, lastError?, sendMode, commands, enabled, replyMaxChars, lastInboundAt?, lastOutboundAt? }` (`enabled` is the binding's own switch, `replyMaxChars` the limit in effect), `send(bindingId, text, options?: { notBefore?: number })` (throws when the binding cannot send; `notBefore` holds the entry until then), `route(bindingId, { chat, notBefore?: number })` (chooses whether the running turn's final text goes to the chat; false when no turn is running), `setOptions({ replyMaxChars?, enabled? })`, and for the parent's WeChat settings panel `setBindingOptions(bindingId, { sendMode?, commands?, enabled?, replyMaxChars?, mediaDir? })` returning the new status, with no write and no event when nothing changed, `reconnect(bindingId)` resolving with the status after the first poll, and `diagnose(bindingId)` resolving with `{ ok, checks: { label, ok, detail? }[] }`. Events: `im-robot/inbound(sessionId, channel)` before each prompt or command (listeners awaited), `im-robot/status(bindingId, state)` on every binding change except message times alone.
- Register no tool, no prompt, and no command: sessions without a binding must behave exactly as without the plugin. A `/` line from the chat runs commands other plugins registered, through the host's `commands` registry, read with `ctx.get` (no injection). Asking the model to wrap structured content in `<keep>…</keep>` is the parent package's prompt; this plugin only honors and removes the markers (`KEEP_OPEN`, `KEEP_CLOSE`, exported). Likewise the parent sends its own notes (heartbeats, watchdog) with `agent.followup` and a message source of kind `host-note`, so they do not count as web input.
- Secrets live only in `ctx.credentials` under `IM_ROBOT_WECHAT_<bindingId>` (`_` and `-` in the id escaped as `_5F` and `_2D`); everything else in `$DSH_HOME/plugin-data/im-robot/<bindingId>.json`, mode 0600. `unbind` removes both.
- Reliability: a failed poll reconnects with exponential backoff (2 s doubling, at most 5 min) and the loop never ends on its own; an expired or missing token sets `connected: false` with the plain-Chinese "login expired, bind again" `lastError` (`CONNECTION_PROBLEM.expired`) and emits `im-robot/status`. Every final reply segment is written to the binding's `outbox` before it is sent and removed once sent; after the next successful poll (so after a reconnect or restart) unsent entries under 24 hours old are retried with their own `context_token`, and an entry that has failed more than three times is dropped with a log line only. Answers to follow-ups (worker reports, agent and team messages, host notes) and `send` use the outbox too; reminder pushes and notices bypass it and are never retried. A send refused before the account ever wrote (no reply context exists yet) counts no failure: the outbox waits for its first message, within the 24 hours.
- Only the person who scanned is accepted, only in a private chat. No group chats in this version.
- Media goes to the binding's `mediaDir` (absolute), else `plugin-data/im-robot/media/<bindingId>`; a saved name never leaves that folder, and a download comes only from an https Tencent host or the configured CDN. A file that cannot be saved is named in the prompt with the reason, so the session can tell the person. Nothing here deletes saved files.
- A turn during which `send` was called sends no automatic reply and no "no reply" notice: the caller has answered.
- Code comes only from MIT sources: `@tencent-weixin/openclaw-weixin` 2.4.10 and `dsh-weixin-ilink` 0.9.1 (never its files derived from dsh-plugin-weixin). Nothing from the Apache-2.0 `@michengai/dsh-im-connect`. Every adapted file states source, license, and changes in its header; `THIRD_PARTY_NOTICES.md` carries both copyright lines and license texts.
- Runtime imports are limited to `@deepseek-ai/cordis`, `@deepseek-ai/schemastery`, `@deepseek-ai/dsh-credentials`, and Node built-ins; other host types are structural mirrors.
- Package identity: `@starsharryzhu/im-robot` version `0.2.3`, MIT, `engines.dsh` `>=0.2.1-rc.5 <0.3.0-0`, the same range for the `dsh-credentials` peer; `tests/manifest.test.ts` pins them.
- Every host version in that range must work, including 0.2.1-rc.5 (the user's Desktop): check a host method that newer hosts added before calling it. `agentPresets.presetForSession` only exists from 0.2.2-alpha.2, so it is called when present, else `sessionProjections.stateOf(session, 'agentPreset')`, which newer hosts deprecate. Do not use `sessionController.presetForSession`: the public controller has no such method on any version.
- A failure in this plugin must not reach the host: the `session/event` listener and `start` log it, and the outgoing queue never rejects.
- `lib/` is generated by `node build.js` and committed, because `link:` and git installs do not build.
- Every folder carries this four-section English file; `tests/agents-md.test.ts` enforces it.

## 3. Contents

- `src` — plugin source: entry, service, turn tracking, reply formatting, state files, and the channel adapters.
- `tests` — vitest specs against a fake iLink HTTP server and fake host services, plus manifest and documentation checks.
- `scripts` — the development toolchain linker.
- `locale` — Plugins page title and description in English and Chinese.
- `lib` — generated build output (committed).
- `build.js` — type-check, emit `lib/`, and self-check the entry against a fake host.
- `cordis.patch.yml` — the bundle patch for a standalone install: one top-level row.
- `package.json` — identity, peers, engine range, and `dsh.bundle.patch`.
- `tsconfig.json` — type-check settings.
- `tsconfig.build.json` — emit settings for `lib/`.
- `vitest.config.ts` — test runner settings.
- `README.md` — user documentation in Chinese.
- `THIRD_PARTY_NOTICES.md` — copyright lines and license texts of the adapted MIT sources.
- `.github/workflows/publish.yml` — tag-triggered npm publish through trusted publishing (OIDC), with no stored token.
- `.gitignore` — ignores dependencies and local notes, keeps `lib/`.
